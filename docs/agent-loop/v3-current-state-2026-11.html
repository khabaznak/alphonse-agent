How Alphonse processes a request

The V3 runtime has an outer strategy loop and an inner action loop. Jev supplies bounded judgments; System Two generates language and plans; deterministic code controls access and execution.

1 / The outer loop

A task moves through admission, planning, execution and review. A completed phase may lead to another phase.

How to read this

Admission can route a straightforward request to a direct System Two response. Otherwise, the planner creates a phase and the executor works through it. Outer review can request another phase, including a response-only phase.

Controls across the flow

Authorization, scope, cancellation, checkpoints and effect verification are enforced by runtime code. Jev relevance does not grant access.

2 / Inside the tactical executor

The inner loop selects and reviews one action at a time until the subgoal completes, blocks or is interrupted.

The Gmail run

Five memory searches + four source reads stayed in the same subgoal. Each was followed by a Jev review; the recorded run never reached the planned reply. Historical memory could not establish a current unread count.

Where context grows

The current action-selection prompt includes the complete untruncated execution log. Repeated searches can therefore increase the next prompt substantially.
