# Gym cycle: multi-source answer and decision format

Development cycle, 13 November 2026 (America/Mexico_City). These are synthetic
fixtures, not household conversations, clinical validation or release
qualification. All nine attempts used the existing signed-in Codex subscription
provider with requested model `gpt-6-luna`, no Jev, a 35-second per-call timeout
and a 90-second task deadline. Actual provider token usage and recipient delivery
were not observed. One attempt per configuration is not a reliability estimate.

## Failure and changes

The earlier clarified prescription-v2 diagnostic returned the expected-looking
answer but did not read the conversation and treatment-status sources required
by the independent post-run oracle. This cycle used `matched_provenance`: the
candidate was not given the oracle's required-source list or its assessment.

The new baseline read all three substantive sources but blocked without an
answer. Its trace records four tool decisions then an unrecognized decision;
the trace did not retain the raw decision or exact blocker. Given the candidate
code, an invalid decision shape is a plausible immediate cause, not an observed
exact reason. A general candidate change gives one budgeted, checkpointed
format-repair opportunity without executing or echoing an invalid action. The
retry is still subject to the existing cancellation, freshness, read-only tool,
authorization and budget checks. Synthetic tests exercise the repair, its
bound, restart and cancellation, but neither post-change prescription run
produced an invalid decision, so the live runs do not establish its effect.

After the first post-change prescription still failed on source coverage, a
second change added a general instruction to the **synthetic Codex chooser** to
consider other relevant authorized sources that could change a conclusion. It
does not name the fixture's required sources or supply the answer key. This is
an evaluation-chooser change, not a production prompt or a model-weight update.

| Synthetic inbox baseline / repair / both changes | Pass / pass / pass | Mailbox read in each | 10.84 / 8.07 / 8.92 s | 2 each |

Prescription source coverage is assessed after the run, independently of the
candidate's completion status; a correct-looking answer without all required
observations fails this development oracle. The two later prescription runs
failed despite returning `completed`. A single extra source read in the second
run is not evidence of improved reliability. The clock and inbox outcomes do
not establish non-regression or a speed difference from one trial per version.
The 22 counted model calls are observed call events, not a token or cost total.

Every attempt has a separate fsynced start, categorical traces, final runner
result, and source hashes in `evidence/gym-cycle-2026-11-13/`. The existing
runner deliberately omits raw model decisions and answer text, so these are not
full transcripts. The loopback source uses a bearer capability; process
identity, answer-formation order, actual delivery and billing are unverified.
The reason-category mapping was improved after the attempts to distinguish a
future `candidate_decision_invalid` from generic `other`; this does not change
or retrospectively explain any receipt.

## Held-out separation and next work

Four separately authored synthetic evaluator pilot cases and answer keys were
frozen separately outside the repository; see [the seal](heldout-pilot-seal-2026-11.md).
They have not been run and were not used to write the two changes. This is not
a qualification-grade held-out corpus: same-user filesystem access is not
isolation, independent review and executable scoring remain missing, and four
cases in one family fall short of the wider protocol. Replace the set if its
content is exposed during development, and establish independently reviewed,
sequestered scoring and broader coverage before qualification.

The concrete next problem remains selecting and inspecting relevant authorized
sources before answering, without a hidden oracle telling the candidate what to
read. A future change needs an independently scored development run and other
cases; prompt wording alone did not demonstrate that problem was fixed. The
candidate is not registered for household conversations, and production
authorization, delivery and recovery gates remain open.
