# Evaluation support-module review — 14 November 2026

Companion to `evaluation-arm-retirement-audit-2026-11.md` for #229. This
reviews the seventeen named support modules individually; it is not an inventory
of every evaluation helper. “Active” means an in-repository consumer exists,
not that a live evaluation is running or authorized. The historical V3 bridge
and related fixtures are not evidence of simpler-loop qualification. No
provider was called for this review.

| Module | Classification and present value | Current consumer or evidence | Decision |
| --- | --- | --- | --- |
| `benchmark_summary` | Active offline measurement utility: counts expected/observed synthetic attempts, including missing ones; not a source of independent oracle or cost attestation. | `synthetic_journal_summary` imports `summarize`; `test_benchmark_summary.py` checks accounting. | Retain: deleting it breaks the existing journal summary. |
| `codex_subscription_provider` | Active **evaluation-only** Codex subscription adapter and sign-in preflight; not a sandbox, live-call authorization, or proof billing cannot change mid-call. | Imported by the current Codex clock, mail, prescription and candidate chooser evaluation modules; `test_codex_subscription_provider.py` covers its behavior. | Retain for current synthetic gym comparisons. |
| `decision_followthrough_development` | Active scripted follow-through fixtures and independent expected values for synthetic development cases; its in-process audit is not a real delivery receipt. | Both candidate and V3 follow-through adapters, `question_development` and `denied_followthrough_development` import its cases; `test_decision_followthrough_development.py` covers fixture rules. | Retain while the paired question/denial comparisons use it. |
| `decision_manifest` | Active offline manifest and canonical digest utility; independently anchored descriptions can detect changes, not prove secrecy or evaluator independence. | `read_only_development_manifest` and `small_pilot_plan` import it; `test_decision_manifest.py` checks validation. | Retain for existing experiment descriptions. |
| `decision_traffic_development` | Active synthetic portal and independent fixture oracle, not a real browser/traffic service or held-out benchmark. | `traffic_processor_development` imports its cases, portal and evaluator; `test_decision_traffic_development.py` exercises it. | Retain for the scripted traffic comparison. |
| `heldout_coverage` | Standalone qualification-support checker for supplied structural metadata, with no runtime consumer found; it cannot prove held-out case independence, quality or secrecy. | `test_heldout_coverage.py` exercises required-tag and arm checks; the broader qualification is not yet complete. | Retain provisionally for held-out qualification; reassess after its protocol and use are settled. Test-only use alone is not evidence of actual coverage. |
| `jev_attempt_meter` | Historical V3/Responses pilot support: accounts for each synthetic Jev HTTP attempt without storing request/credential payloads; it is not a hard spend cap or permission to call Jev. | `v3_live_clock` and `v3_clock_responses_attempt` import it; `test_jev_attempt_meter.py` exercises accounting. | Retain with those offline/replay checks until their metering coverage is replaced or retired deliberately. |
| `jev_pilot_http` | Historical V3 pilot opt-in Jev transport; network access, separate authorization and appropriate budget still matter. | `v3_live_clock` imports it; `test_jev_pilot_http.py` uses injected transport and validates boundaries. | Retain with the V3 pilot tests; no new paid call is implied or approved. |
| `jev_pilot_payload` | Supporting canonical Jev request serialization shared by pilot sender and meter. | Imported by `jev_pilot_http`, `jev_attempt_meter`, and `test_jev_pilot_http.py`. | Retain while either consumer remains. |
| `loopback_clock_pilot` | Active disposable synthetic clock source and evaluator; a local capability is not proof of production authority or real-world time. | Used by `codex_clock_comparison`, external fixture runner, and historical clock attempts; `test_loopback_clock_pilot.py` exercises it. | Retain: current clock comparisons depend on it. |
| `loopback_mail_pilot` | Active synthetic unread-count source and evaluator; not Gmail or a real household inbox. | `codex_mail_comparison` imports it; `test_loopback_mail_pilot.py` checks the fixture. | Retain: current inbox comparison depends on it. |
| `loopback_prescription_pilot` | Active invented prescription source and evaluator; not clinical guidance, live data or a security sandbox. | `codex_prescription_comparison`, external fixture runner, and multiple `selective_sources_*` cases import it; `test_loopback_prescription_pilot.py` checks it. | Retain: current multi-source gym cases depend on it. |
| `denied_followthrough_development` | Test-only matched scripted denial comparison across V3, V3 projection and candidate; expected decisions are supplied, so it does not measure autonomous denial handling or production permission. | `test_denied_followthrough_development.py` calls `compare_denied`; the runner imports the shared candidate/V3 follow-through adapters. | Retain provisionally as a distinct three-arm denial control until replaced or judged redundant. |
| `question_development` | Test-only matched scripted missing-identity question comparison; its optional delivery bridge is simulated and does not prove notification or autonomous question choice. | `test_question_development.py` calls `compare_missing_identity`; the runner uses the common candidate/V3 follow-through adapters. | Retain provisionally as a question-specific control while question support remains incomplete. |
| `external_codex_fixture_runner` | Test-only offline reference-fixture wiring for clock, prescription and traffic with an independent answer key; an executor's offline declaration is not a sandbox. | `test_external_codex_fixture_runner.py` exercises `run_fixture`; the runner imports `external_codex_pilot` and loopback fixture evaluators. | Retain to preserve the external-reference plumbing without implying a live external benchmark was run. |
| `heldout_memory` | Historical V3 DC-5 frozen corpus loader and mechanical diagnostics, not rollout approval or proof of independently authored held-out cases. | `paired_memory` calls its loader and assessor; `test_heldout_memory.py` checks frozen input and diagnostics. | Retain while the DC-5 historical comparison and corpus remain executable. |
| `paired_fixture` | Historical V3 boundary evaluation fixture using explicit temporary stores and closed tools; it does not instantiate the normal daemon or prove household behavior. | `paired_memory` imports `run_trial`; `test_paired_memory.py` and `test_heldout_memory.py` exercise it. | Retain as the runtime fixture for the preserved paired-memory baseline. |

No additional removal is justified for these seventeen in this pass. The
standalone held-out checker is a future qualification utility, not proof that a
held-out set or the issue's release criterion is complete. Historical Jev
support should be revisited with the related V3 clock arm rather than removed
in isolation. Reference searches cannot rule out external callers.
