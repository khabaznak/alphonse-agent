# Mixed follow-up contract

The continuity, planner, and scoping reviewers agreed on this contract on November 27, 2026.

## Conversation and requested outcomes

System Two proposes a bounded set of requested outcomes from the current owner message and authenticated steering. Each outcome has a stable ID, a reference to the owner's wording, prerequisites, any named worker, and a disposition. Checkpoint those records under the parent claim. The owner's notes can change priority, relevance, or privacy constraints. The harness validates authority for each proposed action.

A prior private card or citation can be referenced explicitly or resolved from a clear recent reference. Ask which item the owner means when it is ambiguous. Bind the opaque reference to the owner, Desktop turn, exact account and source, authorized label, and source version. Resolve the minimum evidence needed under the current claim and grant. Expiry, deletion, revocation, and changes in source scope make the reference unavailable. Preserve prior action receipts when evidence becomes unavailable.

## Private evidence and delegation

Private Gmail processing runs without tools. Its synthesis is available to the authorized owner view. The parent resumes with its authorized conversation context, an opaque evidence reference, and a fixed availability status. Provider bodies and synthesis stay out of ordinary conversation search, delegation briefs, and audit logs.

The host resolves the named worker and exact target. It builds a structured brief from the authorized operation, target revision, purpose, conditions, and permitted fields. Release of a provider-derived fact requires a current grant for that fact, recipient, and purpose. The first slice uses briefs that need no provider-derived disclosure. Each effect requires its own authorization.

## Receipts and recovery

Track target resolution, submission, worker acceptance, result, and independently verified effect as distinct states. Use a stable actor, parent task, and operation identity with an immutable request digest. Recheck current authority, deadlines, and cancellation at dispatch, receipt pickup, and effect commit. A job continuing after the parent claim requires its own revocable operation authority and fresh claim.

Reconcile a lost acknowledgment by job identity. Preserve uncertainty while the result is unresolved. A blocked or revoked dependency stops the outcomes that rely on it. The owner's other eligible requests can proceed. Report accepted, pending, blocked, and verified outcomes using the receipts that support each one.

## Implementation decisions

Choose reference lifetime and purge behavior, the approved worker transport, and the concrete receipt and independent readback formats during implementation. Start with a disposable worker and a review or patch proposal against a bound repository revision.
