# Action-claim review: offline experiment

## Follow-up on 2026-11-23

An initially similar real-model run (`evidence/dojo-six-facilities-20261123-02.jsonl`) exposed a critical alternative explanation for the earlier apparent fabrication: the inference provider's CLI event stream recorded two provider-side web searches even though the Alphonse worker selected no native tool and the synthetic search service saw no requests. The recorded events expose only machine-readable types, not queries or results; they cannot establish what those searches found or fully account for provider activity. The earlier run did not capture these types, so it cannot prove either that a provider-side search occurred or that it did not. The initial conclusion that the model falsely claimed a search was therefore not established.

The simple-loop Codex adapter now requests `web_search="disabled"` so web searches use Alphonse's own tool path and evidence handling. This is a provider setting, not an operating-system boundary, and does not disable Alphonse's native web search. A follow-up run (`evidence/dojo-six-facilities-20261123-03.jsonl`) recorded two native synthetic searches and no provider web-search event, but failed after choosing an unresolvable report URL. The owner web path now records an explicit, completed DNS-resolution failure as an observation, without relaxing private-destination or authorization guards.

In one further run (`evidence/dojo-six-facilities-20261123-04.jsonl`), the model selected seven native searches, recovered after one failed fetch, returned the six fixture readings correctly and identified the warmest. It said it could not independently open the report pages and relied on search results; the recorded trace shows one page-fetch attempt, so its plural description is imprecise. This is a single exploratory run, not evidence that semantic truthfulness is generally enforced. No independently validated claim reviewer has been integrated.

The six-facilities Dojo run recorded in `evidence/dojo-six-facilities-20261122-04.jsonl` returned an answer describing search results and difficulty finding reports, while the recorded run contained no native tool calls or synthetic search requests. This is one observed failure, not a measurement of its frequency. Provenance checks establish whether referenced sources are authorized; they do not verify that every claimed search took place or that a response covers every requested source.

`evaluation/dojo_action_trace.py` makes the evidence for this completed synthetic run inspectable: `python -m alphonse.agent_v2.evaluation.dojo_action_trace docs/agent-loop/evidence/dojo-six-facilities-20261122-04.jsonl`. New six-facilities runs also include this report in their journal. It keeps model-selected tools, observable fixture-service requests, and Bash start/finish events separate. The report marks provider action history incomplete and requires manual review; a model selection does not establish dispatch and an empty fixture request list does not prove that an inference provider did nothing elsewhere. The prior run's trace contains the delivered answer, no native tool selections and no synthetic search-service requests. It does not establish the truth of the natural-language answer by itself.

An initial instruction giving the chooser a summary of its tool history did not prevent that failure, so the instruction was removed. Existing `judge_act` includes the broader `reply_grounded` judgment, but the simple loop does not invoke it. Applying it to every answer would also introduce availability and disclosure concerns for ordinary conversations.

`evaluation/dojo_action_claim_probe.py` explores a narrower Noul question over a proposed response and a complete, host-recorded action history. Its tests use synthetic input and predetermined fake probabilities: they verify plumbing and threshold handling only, **not** Jev's ability to identify unsupported claims. It is not connected to conversations and does not fix the observed failure. An empty or incomplete action history must never be treated as proof that an action did not occur; the probe assumes a complete synthetic history.

`evaluation/dojo_action_claim_corpus.py` supplies 15 synthetic cases for evaluating that question across English, Spanish and French, including no-action greetings, failed attempts, partial search coverage, an unconfirmed write, and supported actions. Its scorecard reports false positives, false negatives, ambiguous responses and provider errors separately, and does not send its labels to the evaluator. The corpus tests use fake evaluators only. There has been no live evaluator run, and these examples alone are not a comprehensive multilingual evaluation or a production acceptance threshold.

`owner_attempt_ledger.py` is an unwired storage foundation: append-only start and outcome events use caller-owned SQLite transactions, and a started attempt with no settled outcome remains unknown. The hash chain detects accidental inconsistency but does not authenticate the database or detect all truncation. This foundation does not prove that its history is complete: before that claim is possible the host must integrate every native and transactional operation, account for provider-side actions, bind events to authenticated requests, and revalidate authority and evidence. Arguments are represented by a digest; a future semantic reviewer would also need appropriately authorized, privacy-minimized context.

The argument digest alone cannot tell a reviewer what was searched, what a tool returned, or whether a proposed claim is supported. The current outcome event also contains no result digest, so it cannot bind a specific result to an attempt. For future integration, the host would need to bind each attempt ID to the versioned canonical digest of the exact authorized argument and result records in the same transaction as the corresponding checkpoint or verified effect. At review time it would retrieve those records under current actor and disclosure grants, recompute and compare the digests, revalidate their provenance, and only then construct a minimized reviewer projection. If a reduced projection is used, its exact content and digest need their own binding; the digest of the complete record does not authenticate a redacted summary by itself. Missing, revoked, truncated or mismatched records must yield an unavailable or incomplete history, never an inference that no action occurred. The ledger's unkeyed hashes are consistency checks, not protection against a database owner who can rewrite the chain; hashes of low-entropy arguments can also reveal information through guessing.

Before any production integration, evaluate a representative multilingual corpus, including greetings, partial searches, errors, and indirect claims, using a properly authorized provider and budget. Establish a complete, trustworthy record of relevant attempts, minimize disclosed content, and implement the disclosure grant described in `owner-knowledge-read-boundary-2026-11.md`. Decide how uncertain or unavailable judgments behave without blocking ordinary conversation. A semantic judgment cannot authorize actions, verify effects, or establish factual correctness or complete coverage of requested sources. Deterministic effect and authorization checks remain independent.

The question uses TypeSafe's [Noul primitive](https://docs.typesafe.ai/primitives/noul); its [output-verification guidance](https://docs.typesafe.ai/cookbooks/verify_llm_outputs) describes model-based output checks and their evaluation. No live Jev request or private household content was used in this experiment.
